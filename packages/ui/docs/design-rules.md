# Design rules

The registry of design rules titan checks or intends to check, one row per rule. Each rule has a
stable `DR-<family>-NN` id; a revision adds `rN` and an id is never reused. A finding in
`pnpm audit:stories` output that enforces a rule carries that id in its `rule` field (see
[audit-stories.md](./audit-stories.md)), and `scripts/audit-stories/rules.test.mjs` fails when the
audit emits an id this file does not list.

89 rules: 58 M, 31 J.

## Conventions

- **Families:** TY typography, LA layout and spacing, CO colour, hierarchy and elevation, IX
  interaction, MO motion, DD data display, CH charts, RB robustness and system hygiene.
- **Class M** is mechanical and eligible to block. A computed style, DOM geometry, a token or the
  source decides it, and the threshold comes from a normative or practitioner source or an owner
  decision. Blocking goes through a shrink-only baseline.
- **Class J** is judgement and advisory. A reviewer decides the meaning, or the measurement is a
  heuristic with an author-chosen threshold. It is reported as a warning or a critique rubric row and
  never blocks until a recall run promotes it.
- **⚑** marks a rule whose threshold needs an owner decision.
- **Check prefixes:** `DOM:` a computed-style or geometry predicate on the rendered story;
  `SRC:` an ESLint rule or source test; `TOK:` a token unit test; `SHOT:` a screenshot or pixel
  metric; `INT:` needs an interaction driver (focus, hover, press, Escape); `TEST:` a unit test.
- **Source** names the canon the rule rests on. **Merged ids** are the research rule ids folded
  into the row (`R5-*` from the practitioner survey, `b-formal *` from the formal-source survey).
  F-numbers (F1, F9, ...) are the floors in `docs/design-floor.md`.
- **Coverage:** _Yes_ when a shipped check enforces the rule or an open task delivers exactly that
  check; _Part_ when something enforces part of it; _No_ when nothing does. Paths are relative to
  `packages/ui/src/components/` for component files and to `packages/ui/` otherwise, unless they
  start with `docs/` at the repo root.
